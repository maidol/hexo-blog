# 整合请求：判据、设计、执行计划三层区分

级别：B（以文档为主，可能涉及派单/评审模板；落点和措辞由 drsg-harness-kit 决定）
来源：hexo-blog 会话中讨论 review 和验收时总结的内容，用户要求提交给 kit 整合。
关联：

## 要解决的问题

kit 的 `claude/CROSS-PROJECT-REVIEW.md` 里同时出现"判据""设计""实施计划"三个词。目前的写法有：

- "审核方先派判据/任务"
- "执行方出设计和实施计划"
- 设计/计划评审请求包含"需求或收到的判据、成功标准、方案和取舍……实施步骤"

但三者各自该写什么、由谁定、在哪一关审，没有明确界定。用户的 B 级任务由弱模型全程完成，基本都要返工一次。三层混在一起是可能的原因之一：

- 判据缺项，弱模型只能自己补。
- 设计评审和计划评审合在一起草草通过。
- 问题漏到实现阶段，表现为返工。

## 定义

三者回答三个不同的问题：

- **判据**：做成什么样才算对？
- **设计**：用什么方案做到？
- **执行计划**：按什么顺序、分几步做，每步怎么确认？

| | 判据 | 设计 | 执行计划 |
| --- | --- | --- | --- |
| 回答 | 什么算完成、什么算正确 | 结构怎么搭、为什么这样搭 | 先做什么后做什么，每步怎么验证 |
| 关注 | 结果（外部可观察的行为） | 方案（内部结构和取舍） | 过程（步骤、顺序、粒度） |
| 和实现的关系 | 和实现无关，换一种方案判据不变 | 选定一种方案 | 绑定这个方案的落地路径 |
| 必写内容 | 成功标准；边界情况；明确不做的事；验收方式 | 模块划分；接口与数据结构；关键逻辑；备选方案和取舍；影响范围；风险与降级 | 步骤拆分，每步写明改哪些文件、规模、验证命令；依赖顺序；回滚点；每步之后系统可用 |
| 谁来定 | 需求方或审核方 | 审核方或执行方（按级别） | 执行方 |
| 写错的后果 | 方向错，后面全错，而且验收也查不出来 | 方案不成立，或埋下维护和性能隐患 | 步子太大审不动；顺序错导致返工；中途状态不可用 |

## 例子：给登录接口加防暴力破解

**判据**（不提实现）

- 同一账号连续 5 次密码错误后锁定 15 分钟，锁定期间返回明确的错误码。
- 同一 IP 每分钟最多 20 次登录尝试。
- 正常用户输错一次再输对，不受任何影响。
- 不做的事：验证码、短信通知。
- 验收方式：自动化测试覆盖以上每一条；锁定到期后能自动解除。

**设计**（选定方案并说明理由）

- 计数放在 Redis（需要过期能力，也要扛住高频写）。
- 键设计为 `login_fail:{account}` 和 `login_rate:{ip}`，用 TTL 实现自动解锁。
- 在认证中间件里拦截，不改业务层。
- 取舍：Redis 不可用时放行，不拒绝。
- 影响范围：认证中间件和配置项，不碰用户表。

**执行计划**（逐步落地）

1. 配置项和 Redis 计数工具函数，附单元测试，约 80 行。
2. 中间件接入账号锁定逻辑，附集成测试（覆盖 5 次锁定和到期解锁），约 120 行。
3. IP 限流，附测试，约 60 行。
4. Redis 故障降级，附故障注入测试，约 50 行。

每一步都能单独提交、单独验证，做完任何一步系统都可用。

## 规则

1. **依赖方向：判据 → 设计 → 计划。** 评审从上往下：判据没对齐，就不审设计。验收从下往上：每一步按计划验证，最终结果按判据验收。
2. **判据里不写方案。** 比如"用 Redis 记录失败次数"属于设计。写进判据，等于把方案提前锁死；验收时检查的就变成"用没用 Redis"，而不是"有没有防住暴力破解"。判据只写外部可观察的行为。
3. **三层分开评审，各拦各的问题。**
   - 判据评审：拦目标偏差、缺项（边界、不做的事、验收方式）。
   - 设计评审：拦方案不成立、取舍不当、影响范围漏算、缺降级方案。
   - 计划评审：拦步子过大、缺验证步骤、顺序依赖错误、中途不可用。
4. **执行方遇到判据没覆盖的情况时，先问，不要自己补。** 弱模型自行补全判据，是"不是我要的"这类返工的主要来源。

## 和返工原因分类的对应

《强弱模型分工的验收防线》第 4 条提出给验收不通过的原因分类。下表把每类原因对应到最早应该拦住它的那一层，用来判断该收紧哪里：

| 返工原因 | 应在哪一层拦住 | 改进动作 |
| --- | --- | --- |
| 判据缺失、理解偏差 | 判据 | 补判据模板的必写项；判据交由用户或审核方确认 |
| 方案不成立、取舍不当 | 设计 | 收紧设计评审，必须写备选方案和降级 |
| 漏测边界、范围偏移 | 计划 / 验收测试 | 计划里每步写验证命令；验收测试由审核方先定 |
| 钻判据空子 | 判据 + 验收测试 | 判据写"不做的事"；执行方不得修改验收测试 |
| 风格、约定不符 | 计划（引用项目约定） | 派单时附上相关约定，交付前自检 |
